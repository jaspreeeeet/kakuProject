A · Device Start Karo — Step by Step Kya Hoga

Plug in karo aur yeh sequence automatically hoti hai — kuch karne ki zaroorat nahi.

  • 🔌
    Step 1 — Power ON Device ko USB se connect karo ya battery lagao.
    OLED screen ON hoti hai — black screen thodi der ke liye normal hai.
  • 📶
    Step 2 — WiFi Connect hota hai (30 seconds tak wait karta hai) Device WiFi "123" se connect karne ki koshish karta hai.
    ✅ Connect hua → Online mode — server se baat karega.
    ❌ 30s mein connect nahi hua → Offline mode — OLED aur sensors chalte rahenge, server nahi.
  • 🥚
    Step 3 — Egg Hatching Animation OLED screen pe ek anda dikh ta hai jo break hota hai — yeh normal startup animation hai!
    ~3-5 second ki animation. Kuch mat karo, wait karo.
  • 👶
    Step 4 — Baby KAKU Screen pe aata hai Anda break hone ke baad baby left se slide karke aata hai aur OLED pe dikhta hai.
    Yaha se device fully ready hai!
  • 📷
    Step 5 — Camera aur Sensors Start Camera aur MPU-6050 (motion sensor) initialize hote hain. Device motion detect karna shuru kar deta hai.
    Camera OLED pe dikhe wali image nahi deta — yeh sirf detection ke liye use hota hai.
  • ✅
    Step 6 — Main Screen Ready! KAKU OLED pe blinking karta dikhega. Yeh IDLE state hai — sab theek hai.
    Agar online hai toh server se har 2 second mein sync hota rehta hai.

B · OLED Screen Pe Kya Dikh Raha Hai? — Matlab Samjho

😐 IDLE / Blinking Sab theek hai. KAKU theek hai, na bhookha na beemar.
😄 HAPPY Camera ke saamne koi insaan hai ya khush hai. Sparkles dikhenge.
😭 CRY / HUNGER BHOOKHA HAI! Jaldi khana do. Aansu dikh rahe honge.
🍽️ EATING Kha raha hai! Camera se image capture hui aur server ne bhook kam ki.
💩 POOP Potty ho gayi. Dashboard se saaf karo — 15 min mein nahi kiya toh beemar ho jayega.
🤒 SICK (X eyes) Beemar hai. Dashboard se injection do. Health bahut kam ho gayi.
💤 SLEEP (ZZZ) So raha hai. Energy zyada use ho gayi. Kuch mat karo, apne aap uthega.
😔 SAD Khush nahi hai. Khilao ya theek karo. Happiness level kam ho gayi.

E · Karo / Mat Karo

✅ YEH KARO

  • KAKU ke bhookhe hone se pehle camera ke saamne food rakh do
  • Poop icon dikhte hi jaldi clean karo (<15 min mein)
  • Device ko apne saath carry karo — steps count honge aur health achi rahegi
  • Regularly dashboard check karo
  • Server python app.py chalate raho — pet engine wahi hai
  • Agar offline use karna hai toh FINAL.ino firmware use karo

❌ YEH MAT KARO

  • Poop ko 15 min se zyada ignore mat karo — KAKU beemar ho jayega
  • Jab KAKU so raha ho tab disturb mat karo
  • Camera ko permanently cover mat rakho — yeh menu mein phans jayega
  • Server band mat karo — pet engine off hone se hunger/health update nahi hogi
  • Ek saath multiple injections mat do agar health pehle se 80%+ hai
Yaad rakho: KAKU ek virtual pet hai jisko real care chahiye! Jitna zyada dhyan doge, utna healthy aur happy rahega. Server-side pet engine har 60 second mein KAKU ki condition check karta hai — toh agar aap 10 minute ke liye bhi dhyan nahi dete, KAKU ko fark padta hai. 🐾

1 · System Overview

KAKU is a connected Tamagotchi-style pet device. The XIAO ESP32 S3 Sense handles real-time display, camera-based interaction, and sensor reading. A Flask/SocketIO cloud server (Google Cloud Run) acts as the pet's "brain" — tracking state, hunger, health, and serving display commands back to the device. Two firmware files exist: esp32_sketch.ino (full cloud-connected mode) and 16_TAMAGOTCHI_CAMERA_FINAL.ino (standalone offline mode).

3 · Current System Status

✅ Active & Enabled

  • MPU-6050 accelerometer / gyro
  • OLED animation (FreeRTOS Core 0, ~30 FPS)
  • WiFi HTTP POST sensor data (Core 1)
  • Binary camera image upload (POST /upload)
  • Pet state poll every 2 s (GET /api/oled-display/get)
  • Step counter — server-side detection
  • Orientation — server-side computation
  • Camera person detection (NEAR / FAR)
  • Menu via camera cover gestures
  • Pet engine background thread (60 s cycle)
  • SQLite DB — database-only image storage (BLOB)
  • WebSocket real-time dashboard broadcast

⚠️ Disabled / Commented Out

  • Audio recording & upload (I2S PDM)
  • Shake-based feeding (replaced by camera)
  • File-system image storage (DB only now)
  • Background AI analysis (non-blocking)
  • File-system image cleanup thread
  • Orientation endpoint on ESP32 (server computes)
  • loadState() saved preferences (testing mode)
  • AI Vision: depends on server env — FULL/BASIC/NONE
